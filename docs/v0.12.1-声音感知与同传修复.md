# v0.12.1：声音感知、光晕修复与同传修复

## 现在怎样开启

打开 **手机自定义设置 → 声音感知**，不再进入深层菜单寻找两个独立模块。

“开启声音感知”同时启动本地声音类型识别，并尝试连接已保存的小板或已识别的 CH340。需要时按系统提示允许 USB 和麦克风访问。没有小板时仍可识别类型，连接小板后有方位光晕。多个同型号设备需在“小板连接与详细校准”明确选择。

“停止声音感知”停止本地环境音与小板读取。若单独开启了云端语音字幕，该字幕功能仍按自己的设置运行。环境音在本机处理，不会因此自动开启云字幕。

本次开启期间，离开应用会暂停采集，返回前台恢复；彻底退出后不自动打开麦克风。系统授权弹窗返回后会继续这次开启操作。

## 为什么此前只有数字条

v0.12.0 的视频合成分支把光晕入口绑定到了“环境音识别已开启”；分类未开启时仍调用旧的方向条。这是本次修复的应用接入遗漏。

v0.12.1 已移除旧的箭头 / 数字方向条：

- 小板有新鲜有效角度，即使未开声音分类、未打开麦克风，也显示蓝色方位光晕。
- 尚无声音类型时只显示光晕，不虚构“门铃”“泼水”等名称。
- 识别出类型后，继续显示磨砂名称标签；名称与方位仍只是时间关联估计。
- 小板停止更新时，在所设超时内淡出；断开或关闭方向显示时清除光晕。
- 数字角度仍可在“声音感知”的状态和详细校准页查看。

前方基准、左右校准、光晕亮度及样式继续保留。当前手机升级时的前方基准为 95°，逆时针。若把光晕亮度主动调为 0 或关闭“显示方位光晕”，则不会显示方位光晕。

## 设置界面

主设置的横屏模式仍为左侧文字、右侧模式条；标题和选中值重新调整字号、间距及垂直位置。开关和模式条继续统一蓝色。

**X 键弹出的字幕语言小窗恢复原来的上下布局**：上方标题，中间选中语言，下方完整宽度的模式条，再下方显示操作说明。它不再使用主设置的左右列布局，触摸命中区域也同步恢复。

## 同传 API 的实际结论

模型保持用户指定的 `qwen3.8-livetranslate-flash-realtime`。问题不是模型名错误或 Key 失效：

1. 用手机已保存的同一 Key，原请求通过了 WebSocket 鉴权，但服务端创建会话时给出 `Chelsie` 默认音色，发送公开测试音频后报 `Voice 'Chelsie' is not supported`。
2. 保持 Key、模型和音频不变，只增加 `session.audio.output.voice = "Tina"`，服务端实际配置变为 `Tina`，返回了原文、译文和 `session.finished`。
3. 将该参数写入正式客户端后，再通过实际 `SpeechClient → CaptionTranscript` 路径复测，原文和译文字幕均非空并正常结束。

因此，这是**服务端默认音色不兼容，加上应用此前没有显式覆盖默认值**的问题；目前通过应用请求参数修复，不需要先在控制台更换权限或模型。

官方文档描述该模型默认音色为 `Tina`，与本次实际收到的 `Chelsie` 不同：[阿里云同传说明](https://help.aliyun.com/zh/model-studio/qwen3-5-livetranslate-flash-realtime)、[服务端会话配置](https://help.aliyun.com/zh/model-studio/live-translator-server-events)。

## Key 的默认填入

手机原有 Key 已在本机重新保存，并通过真实请求核验。打开语音配置页时自动填入密码框；新增“保存为本机默认 Key”按钮。覆盖升级保留保存值，无需重复输入。

Key 由 Android Keystore 加密保存在这台手机，不写入源码、APK 或诊断日志。若以后主动清除应用数据 / 卸载，或临时 Key 到期，仍需重新提供可用 Key。

详细参数入口：手机自定义设置 → 深层设置 → 语音接口配置与测试。此配置入口与浅层“字幕语言”开关分开，避免日常观看误改凭据。
