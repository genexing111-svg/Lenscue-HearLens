## 10 分钟固定参数结果

最终安装包于北京时间 2026-09-25 16:48:50–16:58:50 完成 **600.01 秒**双向回传，通过。601 次 HTTP 状态采样全部成功；同一主摄、同一会话和同一回传拥有者，源帧与回传帧持续推进，没有超过 3 秒的停帧或不健康状态记录。`HearLensDisplay` 日志在进入双眼模式后没有退出、暂停或重建事件。

固定参数：自动帧率，主摄 1×，源图 640×480，JPEG 75，回传画布 960×432，双眼完整图，文字字号基准 36，软件亮度/对比度/饱和度均 100%，不旋转、不镜像、不显示校准图。电脑只有一个源图流，保持观看页面可见。

| 环节 | 601 个窗口读数的平均 FPS | 最低 / 最高窗口读数 |
| --- | ---: | ---: |
| 相机采集 | 60.04 | 59.59 / 60.50 |
| USB 上行 | 59.37 | 56.74 / 60.59 |
| 手机收到回传 | 58.28 | 29.22 / 60.73 |
| 手机 View 绘制 | **53.46** | **27.23 / 59.48** |

这些是最近约 2 秒窗口的回调计数，短窗口有计时抖动。手机绘制不是物理屏幕扫描测量；**存在短时掉帧，不能称为稳定 60 fps**。采样最大间隔 1.016 秒，是采样上界，不是画面端到端延迟。本次没有测出 USB 带宽极限，也不保证更高分辨率达到同样速度。

测试前后电池传感器温度为 **36.4°C → 35.4°C**，Android Thermal Status 均为 **0**。这只是当时环境与传感器读数，不是眼镜内封闭佩戴时的完整温升认证。应用 PSS 从刚启动约 65 MiB 到运行后约 166 MiB；前者尚未完成解码/显示预热，不能拿这两点证明不存在内存泄漏。原始温度、热状态与内存记录保留在交付目录。

长测之后又完成最终构建的 20 次切镜（`verified-final-switches.json`），全部恢复真实双向帧，并保持双眼模式。物理恢复检查过程中用户也更换过镜头和重新打开控制台，因此那段操作记录不用于计算稳定帧率或纯粹重连耗时。

开发复测发现两处多页面问题并已修复：旧版无 ID 的显示指令能影响新版拥有者；当前回传页面可能取不到被其他页面占满的源图通道。回传归属、独立显示代际、显示命令先后顺序和优先源流共同处理这些情况。

其后两轮追加切镜复测分别完成 8 次、3 次后，手机退出双眼显示，未计为通过。用户不能确定是否有手动操作；本应用退出历史没有相应进程崩溃记录，因此不能据此断言自动退出或操作原因。最终版加入 `HearLensDisplay` 生命周期/开关诊断，只记录事件，不记录图像或文字；之后固定 10 分钟和 20 次切镜均通过，未再次出现退出。保留原失败记录供区分。

## 事实边界

手机只向普通应用开放两个顶层相机入口，但后置逻辑相机公布三个物理 ID。物理 ID 可枚举不等于可以成功创建预览＋分析会话；必须验证真实帧输出。

双眼显示同一相机画面，未实现双摄立体、头部追踪或镜片畸变校准。软件校准图用于对齐，不是近视矫正。真实佩戴舒适度和屈光矫正效果需要用户验证。
