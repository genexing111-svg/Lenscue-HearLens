# v0.5.1 局域网接口

所有视频均由手机采集、在手机合成。本接口可让未来的电脑语音识别程序把文字发送给手机，不需要重新设计显示链路。

手机开启无线共享后显示 `http://IP:18766/#KEY`。`BASE=http://IP:18766`；`KEY` 是 `#` 后的 32 位访问密钥。请求头必须有 `X-HearLens-Key: KEY`。不要把用户字幕、密钥或摄像头画面发到第三方站点。

服务只监听手机 Wi-Fi / 热点接口，非公网服务。不发送跨源允许头。浏览器通过手机提供的同源控制台使用；独立电脑程序可直接请求。POST 带 Origin 时必须与 BASE 相同。

## 发送/清空字幕

```
POST /subtitle
X-HearLens-Key: KEY
Content-Type: application/json

{"text":"右后方：泼水声"}
```

这只是文字示例，不表示应用已能识别声音或方向。将 `text` 设为空字符串可清空。最多 120 个 UTF-16 代码单元（普通汉字 120 字，表情可能占两个单元）。当前字幕被下一次提交替换，不排队、不保留历史。字幕持续显示至清空或应用会话结束。返回 `200 {"ok":true}` 表示已接受，下一帧本地合成时绘制到两眼。网络断开可重发同样内容；只连接自己的手机。

PowerShell 示例（将占位值换成手机当前链接）：

```powershell
$hearlensBase = 'http://手机IP:18766'
$hearlensKey = '完整链接中#后面的密钥'
$hearlensBody = @{ text = '字幕接口测试' } | ConvertTo-Json -Compress
Invoke-RestMethod -Uri ($hearlensBase + '/subtitle') -Method Post `
  -Headers @{ 'X-HearLens-Key' = $hearlensKey } `
  -ContentType 'application/json; charset=utf-8' `
  -Body ([Text.Encoding]::UTF8.GetBytes($hearlensBody))
```

## 状态与视频

- `GET /status`：JSON。`stereo.localFps` 是本地输入帧率，`phoneDisplayFps` 是手机实际绘制新帧的帧率，`wirelessEncodeFps` 是无线编码帧率；`sourceWidth/sourceHeight` 是采集尺寸，`phoneWidth/phoneHeight` 是手机画布尺寸，`width/height` 是无线 JPEG 尺寸，`hardwareCanvas` 表示手机是否使用硬件画布。另有 `frameId`、`ageMs`、`settings`。`cameras`、`cameraControls`、`selectedCameraId` 为真实镜头及能力。旧 USB 诊断字段为兼容源码保留，v0.5 无线流程以 `transport=phone-local-wifi` 与 `stereo` 为准。
- `GET /frame.jpg?after=上一帧编号`：最新双眼 JPEG，最多等待 600 ms。收到 `200` 时读取 `X-Frame-Id`；没有新鲜画面时返回 `204`。一个客户端每次只保留一个未完成请求，取到后再取下一帧，不并行排队。JPEG 已含两眼及字幕，不应再切割或合成。
- 无新帧时清除过期画面；断线后间隔 250–2000 ms 重试。应用进程重启会重置帧编号，重新连接时将 `after` 设为 −1。

## 设置接口

- `POST /layout`：提交画面设置的部分 JSON 字段。例如 `{"fontSize":44,"textY":75,"background":82}`。字段范围见手机自定义界面；`GET /status` 中 `stereo.settings` 给出完整字段。
- `POST /camera`：单独提交 `{"cameraId":"实际返回的ID"}` 切镜头；或提交当前镜头的 `fps / maxWidth / zoomRatio / exposureIndex / torch`。`fps=0` 自动选择当前普通相机组合支持的最高帧率；`maxWidth` 为采集尺寸档，实际尺寸读取状态。旧 `quality` 字段仅为兼容旧 JPEG 采集路径保留，不影响 v0.5.1 本地手机画质；无线 JPEG 质量应通过 `/layout` 的 `wirelessQuality` 调整。镜头切换与其他参数分开提交，并等待状态确认。无效 ID / 超出能力范围返回 400。
- `POST /focus`：`{"action":"center"}`，请求当前镜头中心对焦和测光。

错误：无效密钥返回 403；无效类型、未知字段、越界参数返回 400；过大请求体返回 413 或直接关闭连接。只支持固定 Content-Length，请求体上限 16 KiB。最多 8 个并发 HTTP 处理，每个连接有截止时间；网络阻塞不会阻塞手机本地合成。电脑建议只开一个观看页。

只有需要发送字幕的电脑程序持有密钥即可。这里没有自动识别模块，也不需要麦克风或存储权限。


## v0.6.0 新增接口

同样要求 `X-HearLens-Key`，仅在手机应用前台、无线共享开启时可用。

- `POST /layout` 新增 `phoneRenderWidth`（0 表示屏幕最高；其余为受支持的总宽度档）、`phoneFps`（0 自动或 15/24/30/45/60/90/120 上限）、`wirelessAdaptive`（布尔值）。超过物理屏幕的合法宽度档会限制到屏幕最高，不改变源图采集尺寸。
- `POST /view`，JSON `{ "stereo": true }` 进入双眼，false 退出。成功响应表示请求已接收，最终状态查看 `/status` 的 `vrEnabled`。
- `POST /remote-calibration`，JSON `{ "start": true }` 开始四键逐项校准，false 取消。需要用户在手机端实际按键；查看 `stereo.remoteLearning` 当前要求的字母，完成后为 null。
- `POST /network-feedback`，JSON `{ "transportMs": 120 }`。0–10000 毫秒的接收与解码耗时，浏览器扣除响应头 `X-Wait-Ms` 的服务器等待时间后自动上报。限频处理；这是自适应反馈，不是端到端摄像头延迟。
- `/status` 新增 `stereo.renderWidth/renderHeight`（实际 GPU 画布）、`renderTargetFps/renderCostMs/renderError`、`phoneResolutionOptions`、`wirelessTargetFps/wirelessEffectiveQuality/wirelessAdaptiveLevel`、`remoteStatus/remoteEvents/remoteLearning`。原有镜头、文字与布局字段继续可用。

源图、手机 GPU 画布、无线 JPEG 的分辨率是三个独立参数。不要将 `stereo.width/height`（无线输出）当成手机显示分辨率。
