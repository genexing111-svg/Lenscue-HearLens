## SC-B03 校准

最初未收到按键时，系统输入设备列表中遥控器已断开，且通知栏获得输入焦点；重新连接并回到应用后收到摇杆事件。随后发现实体字母并不采用标准游戏手柄字母键码。最终使用应用内逐项提示校准，用户确认完成四步；应用记录与保存如下：

| 实体键 | 本次 Android 事件 | 保存后的功能 |
| --- | --- | --- |
| A | KEYCODE_VOLUME_DOWN / 25 | 确认 / 增加 |
| X | KEYCODE_VOLUME_UP / 24 | 开关菜单 |
| B | KEYCODE_BUTTON_B / 97 | 关闭菜单 |
| Y | KEYCODE_BUTTON_START / 108 | 减少 |

四个方向的摇杆事件均已接收；手机设置值曾随摇杆操作改变。映射写入应用私有偏好。鼠标按钮兼容逻辑已实现，本轮实际四键采用上表事件，没有另行声称验证了所有遥控器模式。

## 本轮发现及修正

早期候选版本允许长按调整键直接反复重开镜头。测试期间系统厂商 `camera.provider` 曾两次崩溃并自动重启（22:17:39、22:18:42），出现暂时黑屏；不将这些失败隐去，也不把系统服务崩溃写成应用 Kotlin 崩溃。

最终版本把镜头、采集尺寸与采集帧率改为先选择、A 确认才应用，并合并短时间重复的相机重建请求。完成上述 24 次新帧恢复复测后，未再次重启相机服务。手机显示从固定轮询改为按新帧触发，队列最多保留一个绘制回调，减少与相机节奏错开的丢帧。

连续测试准备时发现早前遥控试操作留下了单眼、十字校准和附加 90° 旋转。前一轮只作为约 5 分钟的单眼预检（见 `single-eye-pilot-log.txt`）；恢复 `eyeMode=both`、校准关闭、附加旋转 0 后重新计时。正式双眼记录逐秒保留这些字段。

## 验证边界

最高分辨率指双眼输出画布，单眼源图细节仍受相机采集尺寸、缩放与镜片影响。左右眼复制同一完整源画面，不产生真实立体深度。手机帧率指标为提交新帧到硬件画布的速度，不是光学呈现测速；无线帧间隔也不是摄像头到眼睛的端到端延迟。锁屏、旋转与拔线项目采用用户对本次最终 APK 的新确认，未沿用旧 USB 版的确认。
