# 环境音与光晕接口 v0.12

v0.12.1 修订：光晕由 `LocalStereoEngine` 独立持有渲染器，`SoundHudRouting` 合并实时小板角度与分类事件；不依赖 `EnvironmentSoundSession.enabled` 才显示方向。状态中新增 `stereo.soundHud`（`renderer=edge-glow`、`directionGlowVisible`、`directionBearing`、`classificationActive`、`labelCount`）。旧数字方向条删除。

实时小板光晕与有名称的分类事件分开：只有角度时没有标签，持续输入不会每个数据包重新闪烁，停止更新按小板超时淡出；分类事件仍使用原 2.8 秒曲线。与实时方向相近的分类光晕不重复叠加亮度。统一入口见 v0.12.1 使用说明。

## 模块

| 模块 | 作用 |
| --- | --- |
| `SharedPhoneAudio` | 一个 AudioRecord，多消费者订阅；字幕和环境音各自启停，最后一个订阅结束才释放采集 |
| `PhoneMicrophone` | 手机内置麦克风，16 kHz 单声道 PCM16；环境音共享路径请求 UNPROCESSED / VOICE_RECOGNITION 并尝试关闭可控音效 |
| `EnvironmentAudioFramer` | 保留跨块状态的面积加权重采样；15600 点窗口、7680 点步长 |
| `EnvironmentSoundModel` | 固定 YAMNet + LiteRT 1.4.2 CPU，2 线程；输出原始前 8 类，不做 softmax 或统一阈值过滤 |
| `EnvironmentEventFilter` | 逐项移植交接状态机，普通 / 敲击 / 八类谨慎标签、底噪学习和确认逻辑 |
| `EnvironmentSoundSession` | 手动启动、前台生命周期、一个推理任务加一个可替换的最新等待窗口、会话代次保护 |
| `SoundDirectionAssociation` | 同一音频窗口内的 USB 角度圆周均值；跳动大时不关联 |
| `SoundEventTimeline` | 最多 3 事件，生命周期内同类 / 30° 内方位去重，后来确认可替换“可能”状态 |
| `SoundGlowRenderer` | 手机 GPU shader 与软件光晕，共同几何；名称底板采用局部高斯模糊和原始材质参数 |

模型 SHA-256：`4d8b4a53282dc83ef04e3e7dbc4fbc98082e34e44ed798e16c3a0cdd4c584faf`。

输入 `[15600] FLOAT32`，输出 `[1,521] FLOAT32`。完全并列的分数保留进入排序时的顺序；直接 Interpreter 路径以模型索引升序创建 521 类列表，因此并列按索引稳定排序，可能与其他 SDK 的并列输出顺序不同。

## 既有状态接口的新增字段

已有授权 `GET /status` 下增加 `stereo.environmentSound`：

- `enabled / message`：会话状态。
- `model / modelSha256 / runtime`：固定模型及运行时。
- `audioRoute`：手机音源和可查询处理效果器状态。
- `processedWindows / replacedPendingWindows / inferenceMs`：推理与负载诊断。
- `decision`：原始判定，包含 `kind / event / candidates / noiseFloor / calibrationWindows`。
- `directionAssociation=temporal-estimate-only`：明确是时间关联估计。
- `events`：分类索引、是否“可能”、当前显示名、`bearingDeg`（无关联时 null）、音频窗口接收结束时间与显示启动时间。

不输出录音文件、原始 PCM 或 USB 原始字节，不新增网络开启麦克风或伪造方向事件接口。生产界面没有演示声音注入；测试用事件仅在测试 APK 的离屏渲染检查中存在。

## 时序与空间

判定 `endMs` 使用分窗器累计采样时间，严格保留 >800 ms 间隔清空确认计数的逻辑。方位关联使用手机收到对应音频窗口与 USB 角度的单调时间近似，尚无硬件时间戳同步，不能当作声源身份绑定。

方向统一采用校准后的头部相对角度：0 前 / 90 右 / 180 后 / 270 左。图片镜像不反转头部方向；来源坐标应先转换后再调用显示模块。

光晕按原空间核逐点计算、普通 source-over 合成；API 33 及以上硬件画布使用 AGSL，软件无线画布使用缓存 RGBA。标签局部模糊为 18 参考像素 Gaussian：后台以 3 参考像素的采样网格做有界可分离卷积，最多约每 120 ms 更新一次背景材质，超过 500 ms 的旧材质不继续显示。字体和 GPU 色彩合成存在平台差异，不宣称逐像素等同浏览器截图。

参考分辨率 736×430，标签、留白、模糊和亮边按同一比例缩放。声音标签最多一行，长名称省略；轻微碰撞会向内移动，语音字幕出现时避让其最多四行占用区域。方位光晕不随名称避让移动。

## 资源与复现

冻结判定源码、分窗源码和视觉契约保留在 `docs/environment-reference/`；模型和三语词典在 `app/src/main/assets/environment/`；第三方许可证随 APK 提供。全部音频与判定样例用于单元测试，公开 WAV 与设计背景只打入测试 APK。

运行 `scripts/build.ps1 assembleDebug assembleDebugAndroidTest testDebugUnitTest lintDebug`。真机模型 / 图形测试命令为 `adb shell am instrument -w -e environment 1 com.hearlens.app.test/com.hearlens.app.CaptionRenderInstrumentation`，使用公开样本和设计背景，不打开麦克风。

依据：[LiteRT Android](https://ai.google.dev/edge/litert/android)、[Android 音频源](https://developer.android.com/reference/android/media/MediaRecorder.AudioSource)。判定具体阈值以交接包冻结实现及其 167 帧验证样例为准。
