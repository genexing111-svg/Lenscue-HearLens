## 帧率实测

普通相机元数据与 CameraX 对当前 Preview＋ImageAnalysis 组合的查询均提供最高 `[60,60]`，自动档实际选择这个范围。高速录像列表中的 120/240/480 fps 不用于本版分析与传输管线。[CameraInfo 组合能力说明](https://developer.android.com/reference/androidx/camera/core/CameraInfo)、[高速会话限制](https://developer.android.com/reference/android/hardware/camera2/CameraDevice)。

最终构建稳定运行后采样 20 次、间隔约 1 秒：自动帧率，源图 640×480，JPEG 75，双眼回传画布 960×432。每个读数来自最近约 2 秒的运行窗口，下表为这些读数的均值。

| 环节 | 实测平均 |
| --- | ---: |
| 相机采集回调 | 60.05 fps |
| USB 上行实际发送 | 42.06 fps |
| 手机收到电脑回传 | 40.34 fps |
| 手机 View 绘制 | 40.03 fps |

该段手机绘制窗口读数约为 27.7–49.0 fps，另一次现场面板读数约 50 fps。**不能将其描述成稳定 60 fps 回传。** 自动档取消了旧版 15 fps 人为上限，并尝试当前组合最高采集帧率；结果仍受图像内容、分辨率、JPEG 编解码、浏览器、USB 与温升影响。本次没有测出 USB 接口的物理带宽极限。

最终构建另有 12 秒较高回传分辨率的交互采样：源图 960×720 / JPEG 75，界面被调至回传宽 2560，手机绘制读数均值约 19.08 fps。测试时用户也在调节界面，因此不将这些记录作为严格控制变量的优化前后对比。早期 `roundtrip-1280.json` 等记录属于性能优化前的验证，仅保留作为开发证据。

手机显示计数来自 `View.onDraw`，不是测量物理屏幕扫描完成。页面“回传帧龄”是手机收到 JPEG 后经过的时间，不是摄像头到眼睛的总延迟。没有用电脑和手机的不同时钟相减来声称端到端延迟。

## 尚未验证的边界

- 未完成真实佩戴的融合舒适度、视场角或镜片畸变标定；软件调节是屏幕布局，不能由包装上的瞳距与“45 mm”自动推导光学模型。
- 两眼为同一摄像头画面的副本，没有真正双摄立体深度、头部追踪或空间定位。
- 未做完整的 10 分钟固定参数压力测试、温升测试、物理拔插线、锁屏解锁、前后镜头 20 次切换或两种横屏方向的完整真机回归。不能把代码处理与单元测试当成这些实测已完成。
- 第一次新 APK 安装后，旧版 USB 关闭偏好导致观看页没有响应；读取偏好确认后，用户点“开启 USB 传输”，连接恢复。启动器说明保留这一排查入口。
- 当前为有线 JPEG 逐帧管线，电脑为实际合成节点。后续若需要更高分辨率下接近 60 fps，可进一步评估硬件视频编码；本次没有宣称已实现 H.264、UVC 或 AI 字幕。
