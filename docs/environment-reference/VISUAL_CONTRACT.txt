声音方位光晕与名称标签 · 跨平台视觉契约 · 用户调试定稿

1. 整体视觉

声音所在的屏幕边缘亮起一段蓝色柔光。窄而亮的青蓝边缘向内过渡到宽柔光，
中心画面保留清晰。对应位置有小型灰色磨砂标签，只有一行白色声音名称。
蓝色负责引导方位，磨砂底板负责保持文字可读，二者同步亮起与消失。

当前数值以 spec/design-settings.json 为准。光晕 85% / 80px / 60° 为用户调试值。
蒙版透明度 80% 为用户最终调试值，灰色染色 alpha=0.20。
磨砂材质以 material-reference.png 为参照，以本版成品和参数为复现标准。

2. 方位与坐标

输入 bearingDeg：0° 前、90° 右、180° 后、270° 左；顺时针增加。
前方投射到上沿，后方到下沿，四个 45° 斜向到相应角落。
此处只表示头部相对的水平方位，没有表示声源高度。
世界坐标需先转换为头部坐标；已是头部相对角度则直接使用，避免重复转换。

视图 x 右增、y 下增，宽 W、高 H：
nx = (x-W/2)/(W/2)
ny = (y-H/2)/(H/2)
angle = atan2(nx, -ny)
delta = angle 与 bearing 的圆周最短角距离，范围 [0, pi]
矩形横纵分别归一化，因此角落仍对应 45° 斜向。

3. 光晕空间核

d = max(0, min(x, y, W-x, H-y))
sigmaAngle = (60*pi/180)/2.355
sector = exp(-0.5*(delta/sigmaAngle)^2)
全边参考模式 sector = 1。
core = 0.65*exp(-d/2.2)
ribbon = 0.35*exp(-d/18)
bloom = 0.35*exp(-0.5*(d/80)^2)
alpha = min(1, (core+ribbon+bloom)*sector*0.85)

方向范围是高斯全宽半高 FWHM，不是硬裁切边界，也不是识别置信度。
向内扩散 80px 是 bloom 的高斯 sigma；窄亮边和中间光带仍保留各自衰减。
不要把三个不同尺度合成一个普通大模糊，否则边缘亮度结构会改变。

颜色：near=exp(-d/13)
RGB=(round(48*near), round(114+86*near), 255)
边缘接近 (48,200,255)，向内接近 (0,114,255)。
使用普通 source-over alpha 合成；不要换成 screen，否则纯白场景会失去蓝光。
场景本身保持清楚，仅名称标签下方的局部背景被磨砂模糊。
核函数在 source/glow-kernel.js。可移植为目标平台 shader 或其他材质算法。

4. 名称标签材质与排版

文字只有一行声音类型名称，例如“泼水声”“门铃声”。方位由光晕位置表达。
事件输入见 event.schema.json；不依赖模型输出额外的声音特征描述。
四种声音是演示类别，接入时可扩展类别到展示名称的映射，不限于演示的四种。

材质从后往前：
① 采样标签后方已经合成的场景与蓝光。
② 对背景做局部 Gaussian blur，sigma=18 逻辑参考 px，裁剪在圆角轮廓内。
   采样时读取轮廓外足够范围，再裁剪，防止边缘模糊读取透明色。
③ 普通 alpha 覆盖灰色 rgba(72,74,68,1-T/100)，T 为“蒙版透明度”百分比。
   T 的范围 0–100，步进 1，定稿默认 80，即 tint alpha=0.20。
④ 叠加从上到下的白色微光：顶部 alpha 0.04，底部 alpha 0.01，线性变化。
⑤ 1px 白色边框 alpha 0.22；顶部内高光向下 1px，白色 alpha 0.08。
⑥ 白色文字。底板外为极轻阴影：向下 3px，CSS blur radius 12px，黑色 alpha 0.12。

透明度滑块只调整灰色染色层，白字、18px 背景模糊、浅细边、微光和阴影保持原值。
100% 时灰色填充完全透明，磨砂与浅细边仍保留；0% 时灰色填充完全不透明。
不能把这个滑块当作整个标签组的 opacity，否则文字也会一起消失。
拖动时立即更新已有的所有声音名称底板；松开后保存，恢复状态时继续使用保存值。

灰色取微暖中性，暖场景能透出暖色，暗场景仍有灰色磨砂层次。
不能仅做黑色半透明填充，也不要将底色改回深蓝或加入很亮的蓝色发光边。
外轮廓清楚，圆角抗锯齿，外缘羽化=0；柔软感来自内部背景模糊与轻微明暗。
背景模糊与外阴影的 blur 含义不同，按 CSS 语义映射，不能当成同一 sigma。

排版：15px，font-weight 500，line-height 1.3，白色，默认 Microsoft YaHei 等无衬线字体。
圆角 12px；上下内边距各 8px；左右各 12px；边框额外各 1px。
自然内容宽度，不设最小宽度，不预留另一行空间。三个全宽汉字的参考外框
约 71×37.5px；精确宽度随目标字体字形变化，应使用实际文字测量值。
不加姓名、图标、箭头、标点或方位文本。标签本身没有独立呼吸或脉冲动画。

5. 标签位置

从中心沿 bearing 发出射线，与归一化矩形的边界求交：
nx=sin(bearing)，ny=-cos(bearing)，r=0.5/max(abs(nx),abs(ny))
x=W*(0.5+nx*r)，y=H*(0.5+ny*r)
再按实际标签宽高钳制，使标签外边缘到视图边缘：横向至少 22px，纵向至少 24px。
全边参考标签在上沿中央，中心 y=42px，同样保留上述钳制。
标签不拉伸，不沿四周铺成长条，始终紧凑包裹名称。

6. 时间与多声音

普通事件：0–180ms 平滑亮起，180–1200ms 保持，1200–2800ms 平滑淡出。
smoothstep(t)=t*t*(3-2*t)，亮起用此函数，淡出用 1-smoothstep。
光晕与整个已合成的标签组一起乘同一时间 opacity，不能只淡出字而留下底板。
不自动循环闪烁。减少动态效果模式：静态显示 2600ms，随后移除。
调试用“持续显示”保持在峰值，不是实际声音无限显示的产品规则。

参考实现最多 3 个并行事件；各方向光晕按触发顺序独立 source-over 合成。
最早的事件在第 4 个到来时移除。手动切方位替换上一事件；“两处声音”保留两处。
两个测试事件为右后方泼水和左侧敲门，各自保持名称、位置和生命周期。
相同或很接近的声源事件合并、标签碰撞避让和持续声更新尚未在此原型中定义，
真实事件服务接入时需要另行确定；不要把参考实现当成已完成这些策略。

7. 单位、适配与参考

所有 px 均为逻辑参考尺寸，不是物理像素或毫米。基准预览 736×430。
目标设备先建立 HUD 的视角尺度，再用同一个比例映射标签、亮边与向内扩散；
不要只放大文字，却维持原来的留白或 blur 半径。
在摄像头透视合成里，先有场景与蓝光，再让标签采样该层做磨砂。
跨平台保持层次、alpha 合成方式和时间曲线，不要求 DOM、Canvas、CSS 的具体技术。
本包未进行真实头显、麦克风或定位精度测试。

截图用于整体视觉比对，透明图层与 render-reference.json 用于核对空间数学。
不同字体与渲染器的像素抗锯齿可略有差异，但底板尺寸、层次、颜色与模糊应一致。
淡出动图来自实际浏览器，覆盖峰值到消失，循环只是评审用法。

8. 验收

- 三个光晕默认参数与 JSON、源码、成品都为 85% / 80px / 60°。
- 蒙版透明度默认 80%，灰色 alpha=0.20；0/50/100% 对应灰色 alpha=1/0.5/0。
- 白字 opacity 始终为 1，不随染色透明度改变；事件结束时整个标签组同步淡出。
- 右后事件主要增强右下角，前方在上沿，后方在下沿。
- 中央场景清楚，没有整屏蓝滤镜或整屏背景模糊。
- 三背景的名称标签均为单行白字，灰色磨砂、浅细边、12px 圆角、自然内容宽度。
- 外缘没有羽化，标签下背景有磨砂，标签外场景保留纹理。
- 没有残留底板或图层；瞬时事件约 2.8s 后消失。
- 八方位标签不越界；右后与左侧同时提示时互不遮住。
- 320px 窄屏控件无横向溢出；目标设备复现时保持设计比例。
