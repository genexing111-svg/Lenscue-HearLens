# 最终行为复现规范

本规范描述冻结的成品行为，不是建议接收方重新设计阈值。原型工作流为：采集 PCM → 16 kHz 单声道 → 重叠窗口 → YAMNet → 原始前 8 名 → 有状态判定 → 事件状态及三语名称。

## 1. 模型和 SDK 边界

- 唯一模型：`models/yamnet.tflite`，4,126,810 字节，身份由 `config/final-settings.json` 中的 SHA-256 确定。
- 原始 TFLite 输入 tensor：`waveform_binary`，**shape [15600]、FLOAT32**。输出 tensor：`tower0/network/layer32/final_output`，**shape [1, 521]、FLOAT32**。
- 模型元数据称内部采用 8 位量化；实查含 INT8、FLOAT32、INT32、COMPLEX64 张量。`float32` 下载路径指外部接口，不代表内部所有张量都是 float32。不要另行量化／转模后宣称与本包等价。
- 模型输入就是时域波形。不要先计算 MFCC、mel 频谱或 embedding 再塞给这份模型，也不要对输出再做 softmax 或按总和归一化。
- 原型使用 `@mediapipe/tasks-audio@1.0.1`，CPU，`maxResults: 8`，未设置 SDK `scoreThreshold`、allowlist 或 denylist。
- 每个 975 ms 窗口调用一次同步 `classify(samples,16000)`，取第一个分类结果的第一个分类头。分类器复用，外部负责重叠窗口和异步线程。
- 策略收到的是模型前 8 个候选，不是全部 521 个类别。过滤之后不补入第 9 名。移植时不要把 SDK 全局阈值设成 0.25，否则 0.12 的敲击增强会失效。
- 类别身份使用输出向量索引；三语名字来自 `data/labels.json`，不要用译名做逻辑匹配。

## 2. 音频输入与分窗

输入为单声道归一化线性 PCM float32。若来自 PCM16，除以 32768；不要逐窗口除以峰值或调整响度。浏览器请求关闭回声消除、降噪和自动增益；设备／驱动是否仍处理音频须在目标平台确认。

`capture-worklet.js` 请求单声道，并读取输入第一个通道。严格复现时不要擅自对两个不同方位通道求和。多通道方案属于以后独立设计。

重采样器以 `ratio=sourceRate/16000` 做有状态的面积加权采样平均，跨输入块保留 `sum` 和 `weight`。累加使用双精度，写入 ring buffer 时变成 float32。原来的算法和独立提取版都随包提供；它不是“任意重采样库都能逐样本一致”的承诺。

| 项目 | 数值 |
|---|---:|
| 输出采样率 | 16000 Hz |
| 每个模型窗口 | 15600 点，975 ms |
| 相邻窗口步长 | 7680 点，480 ms |
| 重叠 | 7920 点，495 ms |
| 第一个完整窗口结束时间 | 975 ms |
| 后续结束时间 | 1455、1935、2415… ms |

收集到完整窗口前不推理，不为尾部不足窗口补零。RMS 在重采样后的整个 float32 窗口计算：`sqrt(sum(sample²)/15600)`。峰值为 `max(abs(sample))`；**最终判定代码不使用 peak 作为门槛**，该字段仅保留作观察。

`endMs` 来自音频时间线：累计重采样点数 ÷16。它是窗口结束时间，不是网络到达时间、系统时间或 SDK 的窗口起始时间。

## 3. 调度与生命周期

一次只允许一个分类调用。推理忙时只保留最新的一个待处理窗口，后到窗口替换它，防止队列延迟持续增长。被丢弃的窗口不执行事件判定；保留下来的窗口仍使用其真实 `endMs`，不能伪造连续时间。

新录音会话清空音频缓存、分窗状态、所有 EventFilter 状态。异步结果带会话 generation，旧会话的迟到结果丢弃。切换显示语言不重置以上状态。

每次有效判定先检查：`endMs-lastEndMs > 800` 时清空连续确认计数。**恰好 800 ms 不清空**。所以 480 ms 步长下漏掉一个窗口会产生 960 ms 的间隔，计数必须重置。

参考 Web 的 10 分钟自动停止是演示 UI 的会话管理，不是模型限制；跨平台产品可以另行决定会话时长。

## 4. 三组类别策略

| 策略 | 索引 | 暂定提示 | 单窗口确认 | 连续确认 |
|---|---|---:|---:|---|
| 普通 | 除以下两组外 | ≥0.25 | ≥0.70 | 连续两个处理窗口选中同一主类别 |
| 敲击增强 | 353 Knock、354 Tap | ≥0.12 | ≥0.45 | 连续两个处理窗口选中同一主类别 |
| 定向过滤 | 121–126、129–130 | 先隐藏 | score ≥0.70 且通过音量门槛 | 同一类别连续 3 个处理窗口全部合格 |

定向过滤八类：Insect、Cricket、Mosquito、Fly, housefly、Buzz、Bee, wasp, etc.、Snake、Rattle。Rattle 在字典中是“咔啦响声”；该名称本身不代表检测到蛇。它仍属于这次最终保留的过滤名单。

定向音量条件为严格大于：

```text
rms > max(0.0015, noiseFloor * 2.5)
```

普通声音和敲击增强**不经过上述音量门槛**，也不受任何峰值限制或启动安静校准限制。模型分数保持原始值，0.70 不代表经校准的 70% 识别准确率。

## 5. 背景音量估计的精确规则

背景索引集合为：

```text
67, 68, 81, 103, 494, 500, 501, 502, 503, 504, 505, 506,
507, 508, 509, 510, 511, 512, 513, 514, 515, 520
```

这是背景估计／主标签优先级集合，**不是屏蔽名单**。

初始化：`noiseFloor=0.0025`、历史为空、`calibrationWindows=0`。只有同时满足以下条件才更新底噪：

1. 没有非定向过滤、非背景类别达到其提示门槛（敲击 0.12，其他 0.25）。
2. 不存在“任一定向过滤类别分数 ≥0.70，同时窗口 rms ≥0.03”的情况。

每次更新：

1. 将 rms 截到 `[0.00075,0.025]` 后加入历史，最多保留最新 40 项。
2. 将历史升序排列，取索引 `floor((n-1)*0.2)` 的值为 target；不是线性插值分位数。
3. 前 4 次学习直接 `noiseFloor=target`；以后 `noiseFloor=old*0.9+target*0.1`。
4. `calibrationWindows++`。它只计学习次数，不是等待校准的状态，更不是“等 4 帧才允许识别”。

更新发生在本窗口的定向过滤判断之前。没有普通候选和定向候选时，底噪也参与 quiet 兜底，见下一节；它不把已经达标的普通类别挡掉。

## 6. 每帧处理顺序（应与代码对照）

1. 丢弃索引不在 0–520、非整数索引、非有限分数、分数不在 [0,1] 的项。rms 非有限或非正时按 0 处理。
2. 按原始 score 稳定降序排序；完全相同分数保留上游提供的顺序。
3. 检查时间间隔并按需重置连续计数，然后按上一节学习底噪。
4. 找出满足 ≥0.70 与专属音量条件的定向类别。为每个类别分别累计连续次数，本帧不合格的类别计数立即丢弃。
5. visible 列表保留所有普通类别，以及连续次数已经 ≥3 的定向类别。普通类别没有统一的候选列表分数过滤。
6. lead = visible 中第一个达到自身提示门槛的项；foreground = 第一个达到门槛且不在背景集合的项；knock = 第一个达标的 Knock/Tap。
7. 若 knock 存在且 lead 属于背景集合，选择 foreground 做主类别；否则选择 lead。foreground 可能是分数更高的语音，而不是敲击，不能强行改成“敲击”。
8. 通常显示 visible 的前 3 项。若达标的 knock 不在前 3，则改为 visible 前 2 项加该 knock。**不抬高敲击的原始分数**。
9. 有主类别时更新“连续选中同一类别”的计数；Silence（494）直接输出 quiet。其他类别若已通过定向过滤，或达到单窗口确认阈值，或连续选中 ≥2 次，输出 event；否则输出 possible。
10. 没有主类别时清空主类别连续计数。若本帧有正在累计确认的定向类别，输出 confirming，隐藏具体候选；否则 rms ≤`max(0.0015,noiseFloor*1.8)` 时输出 quiet；其余输出 uncertain 并保留普通候选。

输出 kind 的含义：

| kind | 含义 |
|---|---|
| event | 展示一个已达到本原型确认规则的主类别 |
| possible | 立即展示暂定主类别，例如“可能是敲击声” |
| confirming | 某个定向类别在累计确认，暂不公开具体名称 |
| quiet | 安静／背景噪声；event=null，候选为空 |
| uncertain | 有音频但没有达到主标签条件；event=null，可有普通候选 |

这里的 event 是**当前窗口的展示判定**，不是一次性的事件起点通知。连续帧可能反复给出同一个类别；本包没有事件去重、跨窗口事件段合并或警报消抖以外的产品逻辑。

## 7. 核心接口

```js
import {EventFilter} from './core/event-filter.mjs';
const filter = new EventFilter();
const decision = filter.evaluate({
  categories: [{ index:353, name:'Knock', score:0.1484375 }],
  rms:0.0002,
  peak:0.0004,
  endMs:975
});
// kind:'possible'; event.index:353; 原始 score 仍为 0.1484375。
```

完整字段：`kind`、`event`、`candidates`（最多 3 项）、`noiseFloor`、`calibrationWindows`。类别项为 `{index,name,score}`，name 是模型英文标签；显示时通过 index 查三语词典。

复现计数、阈值和底噪时使用双精度数值，与 JavaScript Number 一致；音频环形缓存和模型输入为 float32。不要把 JSON 中小数阈值先四舍五入为百分数再比较。

## 8. 一致性验证

`fixtures/postprocess-cases.json` 的 expected 由冻结的最终 JS 生成，包含边界值、空白、类别竞争、时间间隔、底噪长期学习和敲击候选保留。每组开始重置状态，逐帧顺序调用，不要把全部帧并行提交给一个状态对象。

`fixtures/audio-framing-cases.json` 附原始 float32 little-endian PCM 和每个预期输出窗口。包内 JS 提取版与原 worklet 已逐字节相同；其他平台可先用归一化 PCM 绝对误差 ≤1e-6 做比较，同时严格检查窗口长度、顺序、采样计数和 endMs。

这些样例证明“相同输入产生相同软件行为”，不证明真实环境音识别准确率。模型推理自检与真实录音评测另见移植说明。
